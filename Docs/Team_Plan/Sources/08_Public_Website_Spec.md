## 1. Purpose
1. Explain the product to station owners in **Arabic and English** and show exactly what it does (plate scan → order → receipt → WhatsApp, face check-in, privacy).
2. Collect **station requests** (Basic / Pro / Enterprise) for the company team.
3. Host the **owner activation page**, where an approved owner sets their own password from the one-time link.

It never shows prices (they are agreed after review), statistics or testimonials that do not exist yet.

## 2. Architecture
```
Visitor ──► Web_Public (Next.js 15, static pages for /ar and /en, port 3002)
              │ browser calls ONLY two public endpoints of the station API (CORS limited to this origin):
              ├─ POST /v1/public/station-requests      (3 per 10 min per IP, honeypot, strict validation)
              ├─ GET  /v1/public/invitations/{token}   (shows station + username for that link)
              └─ POST /v1/public/invitations/activate  (owner chooses password; single use)
```
- Pages are pre-rendered at build time (`generateStaticParams` for `ar`, `en`) → fast, cacheable on any CDN.
- `/` redirects to `/ar` or `/en` (saved choice cookie, else browser language, default Arabic).
- `Brand_Config.ts` holds the placeholder brand (**GarageOS / جراج أو إس**) — rename in one place.

## 4. Data written by the website
| Table | Columns | Who can write / read |
|---|---|---|
| `app.station_requests` | id (UUID, generated by the API), status `new`, plan_code, business_name, business_name_ar, contact_name, contact_phone, contact_email, city, branches_count (1–500), workers_count (1–5000), message (≤ 1000), locale, source_ip_hash (HMAC of IP, never the raw IP), created_at | station API role: **INSERT only**; company Admin API: read + review |
| `app.owner_invitations` | id, tenant_id, user_id, token_hash (SHA-256), expires_at (48 h), used_at, revoked_at, created_by_platform_user | RLS per station; the token itself is never stored |
| `app.users` (owner) | password_hash set, status `invited` → `active`, perm_version + 1 | during activation, inside the station's RLS context |

## 5. Public API contract
### POST `/v1/public/station-requests` → 202
```json
{ "planCode": "pro", "businessName": "Nile Auto Care", "businessNameAr": "نايل لخدمة السيارات",
  "contactName": "Mona", "contactPhone": "+20 100 000 0000", "contactEmail": "", "city": "Giza",
  "branchesCount": 2, "workersCount": 12, "message": "", "locale": "ar", "website": "" }
```
Rules: strict schema (unknown fields rejected), phone `^\+?[0-9 ]{8,20}$`, `website` is a **honeypot** (bots fill it; the API then answers 202 and stores nothing), 3 requests / 10 min / IP → 429.

### GET `/v1/public/invitations/{token}` → 200 / 410
Token = `base64url(stationId) + "." + 32 random bytes`. Returns `{stationName, stationCode, username, displayName, expiresAt, passwordMinLength}` only if the token hash matches, is unused, not revoked, not expired, the owner is still `invited` and the station is active/trial. Otherwise **410 INVITATION_INVALID** (same answer for every failure).

### POST `/v1/public/invitations/activate` → 200 / 410 / 422
`{token, password}`; password ≥ 10 chars, 3 of 4 character classes, not common, not containing the username. Marks the invitation used **atomically** (`UPDATE … WHERE used_at IS NULL … RETURNING`) so double-submits cannot activate twice. 2FA for owners is set up at first sign-in in the mobile app (AUTH-05).

## 8. Run it
```powershell
cd C:\Car_Services_App\Web_Public
npm install
npm run dev
```
Open `http://localhost:3002` (redirects to `/ar`). The form needs the station API running (`Backend: npm run start:dev`) and `PUBLIC_SITE_ORIGIN=http://localhost:3002` in `Backend\.env`.
